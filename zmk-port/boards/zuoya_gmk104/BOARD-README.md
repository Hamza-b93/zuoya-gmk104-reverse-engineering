# ZUOYA GMK104 — ZMK board skeleton (DRAFT / not yet flashed)

A **starting-point** ZMK board for the ZUOYA GMK104 (Telink TLSR9511 / B91, RISC-V),
derived from the sibling [`scholzri/rainy75-zmk`](https://github.com/scholzri/rainy75-zmk)
port of the same Evision platform. **Nothing here has been flashed or verified on hardware
yet** — it is the scaffold described in [`../../docs/05-zmk-porting-plan.md`](../../docs/05-zmk-porting-plan.md).

> ⚠️ Flashing is at your own risk and can brick the board. Read the plan and have the
> stock image + an SWS recovery programmer ready first.

## Known issues to resolve on hardware

1. **Rows 6–7 GPIOs** — the GMK104 uses 8 matrix rows; rainy75 only proved 6. `PD7`/`PE3`
   are educated guesses. Flash a diagnostic/ZMK build and probe GPIO registers (rainy75's
   `boot_diag` method) to confirm.
2. **`RC(7,13)` is duplicated** in the VIA JSON — both `ESC` and the tall numpad key map to
   it. Electrically impossible to share; one is wrong. Probe to find the tall key's real
   cell. The skeleton assigns `ESC` to the top key and `KP_ENTER` to the tall one.
3. **RGB LED count/order** — set `chain-length` to the true count and build the per-key
   position→index map (rainy75's `rainy75_rgb.py` approach).
4. **Encoder** `RC(5,4)/(5,6)/(5,7)` and bottom-right `RC(5,10)/(5,11)/(5,12)` legends are
   guesses (volume/mute, Fn/Menu/RCtrl). Confirm in ZMK Studio.

## Building

This board depends on rainy75-zmk's out-of-tree additions (B91 drivers, the open BLE
controller, the telink HAL + patches, `matrix_transform.h`, `physical_layouts.dtsi`, and the
`telink,b91-*` bindings). **Build it inside a fork of rainy75-zmk:**

1. Fork/clone `scholzri/rainy75-zmk` and set up its west workspace + Zephyr SDK 0.17.0
   exactly as its [`docs/zmk-firmware.md`](https://github.com/scholzri/rainy75-zmk/blob/main/docs/zmk-firmware.md) describes.
2. Copy this directory to `zmk/boards/zuoya_gmk104/` in that workspace.
3. Build the app for `zuoya_gmk104` (mirror rainy75's `build.sh` invocation / west build).
4. Produce the combined MCUboot+ZMK image and the OTA bridge the same way rainy75 does.

## Flashing (no case opening — once images are built)

The GMK104 uses the **identical stock OTA protocol** as rainy75 (same YKQ `KM_USB` v5.0.2
flasher — verified), so rainy75's `reverse/tools/ota_flasher.py` and `install_zmk.sh` flow
applies. Confirm first with the read-only:

```bash
python3 ota_flasher.py --version   # should print the GMK104 firmware version
```

Then follow rainy75's `INSTALL.md` (bridge → MCUboot+ZMK → mcumgr DFU). `restore_stock.sh`
with the extracted stock image reverts.

## Trade-offs (same as rainy75)

USB + Bluetooth LE only (**no 2.4 GHz dongle**), **no screen**, no VIA (use ZMK Studio),
6-key rollover by default.
